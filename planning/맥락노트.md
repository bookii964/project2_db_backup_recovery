## 5. 배운 것

### 검증 원칙
- 이 결과가 확인하려는 설정 덕분인가, 다른 이유 때문인가
- 두 방향 검증: 없을 때 실패하고 있을 때 성공해야 그것이 원인
- 테스트하지 않은 규칙이 틀린 규칙. 고친 뒤에는 회귀 테스트
- 한 도구의 결과를 다른 도구로 교차 확인 (git status vs check-ignore, 화면 vs grep)
- 확인한 사실과 추정을 구분해 기록
- 결과가 기대한 모양과 다르면 다음 명령으로 넘어가지 않음, 오류메시지 잘 읽을 것

### 경로
- 기준점: / 루트, ~/ 홈, 이름으로 시작 = 현재 폴더, .. 한 단계 위. ~이름은 다른 사용자의 홈
- cd - 직전 폴더로, pwd는 Git Bash식(/c/...), pwd -W는 Windows식(C:/...)
- 스크립트는 절대 경로 사용. 파일을 옮기면 상대 링크의 ../ 개수가 달라져 깨짐
- Git Bash는 /로 시작하는 인자를 Windows 경로로 자동 변환 (커밋 메시지 "/planning..." → "C:/Program Files/Git/planning...")
- MSYS_NO_PATHCONV=1로 변환을 끄면, psql·pg_dump에 넘길 경로는 직접 C:/... 형식이어야 함

### 파일 다루기
- ls -la: 숨김 파일까지. 탐색기는 점으로 시작하는 파일과 확장자를 숨김
- touch: 없으면 빈 파일 생성, 있으면 수정 시각만 갱신 (폴더 안 파일 이름까지 지정해야 함)
- rm 파일 / rm -r 폴더 / -f 확인 없이 강제. rm은 휴지통을 거치지 않음
- rmdir은 빈 폴더만 지움(안전장치). 폴더 안에 있으면 그 폴더를 지울 수 없음
- mv는 같은 이름이 있으면 묻지 않고 덮어씀. 지우기 전 mv로 이름을 바꿔 무력화 → 관찰 → 삭제
- grep -n "찾을말" 파일: 파일 내용을 직접 검사 (\.는 진짜 점)
- file 파일: 줄바꿈 형식 확인. echo로 만든 파일은 항상 LF라 VS Code 설정 검증이 안 됨

### 줄바꿈 (CRLF / LF)
- Bash는 CRLF 스크립트를 실행하면 $'\r': command not found
- VS Code files.eol: 내 PC에서 새로 만드는 파일 / .gitattributes: 저장소를 받는 모든 사람
- core.autocrlf=true: 이 PC의 git은 꺼낼 때 LF를 CRLF로 바꿈 → .sh는 .gitattributes로 LF 고정
- VS Code 상태 표시줄의 CRLF→LF 변경은 그 파일 하나만 고침
- files.insertFinalNewline: 마지막 줄바꿈이 없으면 while read가 마지막 줄을 건너뜀

### git
- 네 공간: 작업 폴더 →(add) 스테이징 →(commit) 로컬 저장소 →(push) GitHub
- 보기만: status, diff(작업 폴더↔스테이징), diff --cached(커밋될 내용), log --oneline, show, ls-files, remote -v
- 매번 순서: status → diff → add 파일 → status·diff --cached → commit -m → log --oneline(메시지 확인) → push → status
- git add는 그 순간의 사진. 이후 수정하면 다시 add
- git은 빈 폴더를 추적하지 않음. add만 해도 .git/objects에 내용이 저장됨
- git mv: 덮어쓰기 거부, -n으로 미리 보기. git rm은 파일 삭제 (커밋된 파일은 복원 가능)
- push 후 메시지 수정은 기록 재작성이라 피함. 수정은 push 전 --amend
- 커밋 메시지: 무엇을 바꿨나만. "N번째 커밋" 불필요, /로 시작 금지
- 작성자 이메일은 공개됨 → GitHub noreply 주소 사용
- 프롬프트의 (main)은 상위 폴더 방향으로 찾은 첫 .git의 브랜치 (홈 폴더 저장소 발견 계기)
- git status는 처음 보는 파일은 파일대신 폴더만 보여줌. 추적되지 않는 파일(untracked-file)까지 조회하려면 git status -u사용

### .gitignore
- 한 줄 = 하나의 패턴. 설명·화살표·공백이 든 패턴은 동작하지 않음. 주석은 #
- * 아무 글자, 끝의 / 폴더만, ! 예외
- 추적만 막고 파일 생성은 막지 못함
- check-ignore·check-attr는 실제 파일이 아니라 경로 이름으로 판단. 출력 없음 = 무시 안 됨
- 마크다운의 백틱을 설정 파일에 옮기지 않음
- CRLF로 저장된 빈 줄은 빈 패턴이 되어 /로 끝나는 경로 검사에서 착시를 만듦

### Bash 기초
- 터미널은 창, 셸(Bash)은 명령을 해석하는 프로그램
- JSON 설정 파일(settings.json 등)은 전체가 { } 하나의 객체여야 하고 항목은 쉼표로 구분. 객체가 두 개거나 쉼표가 빠지면 프로그램이 파일을 거부하거나 일부만 적용
- which 명령: 그 명령이 실제로 어느 폴더의 프로그램으로 실행되는지 보여 줌. 오타로 못 찾으면 "no ... in (PATH 목록)" 출력. 같은 도구가 여러 버전 설치됐을 때 어느 것이 쓰이는지 확인하는 데 사용 (예: which psql → /c/Program Files/PostgreSQL/16/bin/psql)
- PATH: 명령을 입력하면 셸이 프로그램을 찾아보는 폴더 목록(환경 변수). 앞에서부터 차례로 찾아 처음 발견한 것을 실행, 어디에도 없으면 command not found
- 옵션: 짧은 형태(-p)와 긴 형태(--parents). 대소문자 구분(git -C는 폴더 지정, -c는 설정값)
- 출력 없음 = 성공 또는 결과 없음인 명령이 많다 → echo $?로 종료 코드 확인 (0 성공, 그 외 실패)
- 쉼표는 명령을 나누지 않음. 나누려면 줄 바꿈, ;(무조건 다음 실행), &&(앞이 성공하면 다음 실행)
- \는 이스케이프(뒤 글자를 특별 취급하지 않음). 따옴표 없는 Windows 경로의 \는 사라짐
- "..." 안에서는 변수가 값으로 바뀜, '...' 안에서는 그대로. 큰따옴표 안의 \+일반 글자는 그대로 남음
- 따옴표를 안 닫으면 > 프롬프트로 다음 줄을 기다림 → Ctrl+C로 빠져나오기
- 명령 속 공백 하나가 대상을 바꿈 (rm -rf ~ /x는 홈 전체가 대상). 경로는 항상 큰따옴표로 감쌈
- Tab 자동완성으로 오타 방지. 패키지 이름 오타는 타이포스쿼팅(악성 패키지) 위험
- 페이저(less): q 종료, Space/b 페이지 이동, /검색. 복사용 출력은 --no-pager

### 변수와 환경 변수
- 변수 설정은 NAME=값 (= 앞뒤 공백 금지), 사용은 $NAME, 삭제는 unset NAME
- export해야 자식 프로그램(psql 등)에 전달됨 = 환경 변수
- 변수는 부모→자식(export한 것만)으로만 전달, 자식→부모는 불가능
- bash 파일: 자식 셸에서 실행 → 끝나면 변수가 사라짐 / source 파일: 현재 셸에서 실행 → 변수가 남음
- source하는 파일에는 exit, set -e를 넣지 않음 (내 터미널이 닫힘)
- export를 빠뜨리면 psql이 기본값(Windows 사용자 이름 등)으로 실행됨 → 멈추지 않고 엉뚱하게 실행되는 게 더 위험

### PostgreSQL 접속
- 포트는 서버의 출입문 번호, 한 서버 안에 DB 여러 개. 5432 원본 서버, 5433 PITR 복구 서버
- pg_stat_archiver는 DB가 아니라 시스템 뷰. postgres는 관리용 기본 DB
- 어디로 접속할지: 옵션(-h -p -U -d) → 없으면 환경 변수(PGHOST, PGPORT, PGUSER, PGDATABASE) → 없으면 기본값
- 비밀번호: pgpass.conf (호스트:포트:DB:사용자:비밀번호, 첫 번째 일치 줄 사용, 비밀번호의 : \는 앞에 \)
- pgpass의 *는 차단이 아니라 "아무거나 허용". 접속을 막는 건 서버 설정(pg_hba.conf)
- 접속 순서: pgpass 조회 → 인증 → DB 존재 확인. 인증 전에는 DB 존재를 알려 주지 않음(정보 노출 최소화)
- -w: 비밀번호를 묻지 않고 바로 실패
- psql 종료 코드: 0 성공, 1 오류, 2 접속 실패, 3 SQL 실행 오류
- 실무에서는 슈퍼유저 대신 백업 전용 최소 권한 계정을 씀
